  <name>Task 2: Add Bearer token auth middleware and route handlers</name>
  <files>src/server.rs</files>
  <action>
    After the Socket.IO removal from Task 1, add the HTTP API layer (RUST-03,
    API-01/02/03/04/05, AUTH-05/07).

    **Auth middleware:**
    Create an `auth_middleware` async function using
    `axum::middleware::from_fn_with_state` that:

    1. Checks the `Authorization` header for `Bearer <token>` (AUTH-05)
    2. Compares the extracted token against `state.token` from AppState
    3. Returns 401 if header is missing, token is wrong, or token is passed
       as a query parameter (AUTH-07 — reject token in query string on API routes)
    4. No token in sessionStorage/cookies — Bearer header only

    For AUTH-07 ("API rejects token passed as query parameter"): the auth
    middleware should check if a `token` query parameter exists and, if so,
    return 401 even if a valid Bearer header is present.  This prevents
    token leakage through URLs/logs.

    **Route handlers (per RUST-03, handlers use State<Arc<AppState>>):**

    1. `GET /` (no auth):
       - Returns `Html(crate::assets::HTML)` with status 200 (API-01)
       - No auth check — the page itself is public
       - The token is still in the QR URL for JS to read (handled in Phase 2)

    2. `GET /api/status` (auth required):
       - Returns JSON: `{ "enabled": bool, "version": "0.3.0" }` (API-02)
       - `enabled` from `keyboard::is_enabled()`
       - `version` from env!("CARGO_PKG_VERSION") or hardcoded "0.3.0"

    3. `GET /api/history` (auth required):
       - Returns JSON array of history strings from state.history (API-03)

    4. `POST /api/commands` (auth required):
       - Accepts JSON body: `{ "type": "type_text", "text": "..." }` or
         `{ "type": "enter" }` or `{ "type": "backspace" }` or
         `{ "type": "clear_pc_field" }` (API-04)
       - Validates the "type" field — returns 400 if missing/unknown
       - For type_text:
         - Returns 400 if text is empty or missing (API-05)
         - Returns 413 if text.len() > 10,000 (API-05)
         - Calls keyboard::queue_type_text()
         - Returns 409 if result is CommandResult::Paused (API-05)
         - Returns 429 if result is CommandResult::Full (API-05)
         - Returns 202 if result is CommandResult::Queued (API-05)
         - On success, adds text to history via add_to_history()
       - For enter: calls keyboard::queue_enter(), returns 202 (or 409/429)
       - For backspace: calls keyboard::queue_backspace(), returns 202 (or 409/429)
       - For clear_pc_field: calls keyboard::queue_select_all()
         then keyboard::queue_backspace(), returns 202 (or 409/429 if either fails)

    **Route structure:**
    ```rust
    let api_routes = Router::new()
        .route("/api/status", get(status_handler))
        .route("/api/history", get(history_handler))
        .route("/api/commands", post(commands_handler))
        .layer(from_fn_with_state(state.clone(), auth_middleware));

    Router::new()
        .route("/", get(index_handler))
        .merge(api_routes)
        .with_state(state)
    ```

    **Request body parsing:**
    Use serde for the commands JSON:
    ```rust
    #[derive(Deserialize)]
    struct CommandPayload {
        #[serde(rename = "type")]
        cmd_type: String,
        text: Option<String>,
    }
    ```

    **Error response bodies:**
    Include a `{ "error": "..." }` JSON body for error responses:
    - 400: `{ "error": "empty text" }` or `{ "error": "unknown command type" }`
    - 409: `{ "error": "paused" }`
    - 413: `{ "error": "text too long" }`
    - 429: `{ "error": "queue full" }`
    - 401: `{ "error": "unauthorized" }`

    Router (including GET /).  Use `axum::middleware::from_fn` or
    `axum::middleware::from_fn_with_state` (no state needed — pure header insertion).

    The middleware wraps `next.run(req).await` and injects these headers into
    the response (SEC-01/02/03/04):

    - `Cache-Control: no-store`
    - `Referrer-Policy: no-referrer`
    - `X-Content-Type-Options: nosniff`
    - `Cross-Origin-Resource-Policy: same-origin`

    **CRITICAL: No CORS headers (AUTH-06)**
    After adding these headers, verify that NO `Access-Control-*` headers are
    present.  Do NOT add any `Access-Control-Allow-Origin` or similar CORS
    headers — axum does not add them by default, but ensure no Axum middleware
    or tower layer injects them.

    Apply to the outer Router:
    ```rust
    Router::new()
        .route("/", get(index_handler))
        .merge(api_routes)
        .layer(from_fn(security_headers_layer))
        .with_state(state)
    ```

    The `security_headers_layer` function:
    ```rust
    async fn security_headers<B>(
        request: http::Request<B>,
        next: middleware::Next<B>,
    ) -> impl IntoResponse {
        let mut response = next.run(request).await;
        let headers = response.headers_mut();
        headers.insert("Cache-Control", HeaderValue::from_static("no-store"));
        headers.insert("Referrer-Policy", HeaderValue::from_static("no-referrer"));
        headers.insert("X-Content-Type-Options", HeaderValue::from_static("nosniff"));
        headers.insert("Cross-Origin-Resource-Policy", HeaderValue::from_static("same-origin"));
        response
    }
    ```

    Add necessary imports: `use axum::response::IntoResponse;`,
    `use axum::http::HeaderValue;`.

    After adding, verify the final build_router() produces a complete, working
    Router with both the auth-protected API routes and security headers on all
    responses.  `cargo check` must pass.

    Note: Place the security headers layer BEFORE the auth layer in the route
    stack so auth errors also get security headers (the inner auth middleware
    returns errors that are then wrapped by the outer security headers middleware).
    Actually, in axum the layer order is from inside out — layers added last are
    outermost.  So: api_routes gets auth layer first, then the merged Router
    gets security layer.  This way security wraps everything including GET /.
