    **C) Inline JavaScript — add a `<script>` tag just before `</body>`:**

    Implement the following logic. Write clean, minimal JS -- no external libraries, no transpilation, no bundling.

    1. **Token extraction** (AUTH-03, AUTH-04):
       - Read `token` from `new URLSearchParams(location.search).get('token')`
       - If token exists: store in `sessionStorage.setItem('token', token)` and remove from URL via `history.replaceState(null, '', '/')`
       - If no token: check `sessionStorage.getItem('token')` — if absent, the page is loaded without auth (show a toast warning)

    2. **fetch helper** (FE-03):
       - Create `api(path, options)` wrapper:
         - Read token from `sessionStorage.getItem('token')`
         - Add `Authorization: Bearer <token>` header
         - Auto-add `Content-Type: application/json` when body present
         - Return fetch promise (caller handles status codes)

    3. **Command queue** (FE-04):
       - Use Promise chain pattern: `let queue = Promise.resolve()`
       - `enqueue(body)`: chain onto queue, return the response for caller inspection
       - Clear textarea and reload history only on 202/ACCEPTED status
       - Show toast on error responses (non-202, non-ok)

    4. **Button handlers**:
       - "Send to PC" button (FE-05):
         - Read textarea.value.trim()
         - If empty, show toast "no text to send" and return
         - Call `enqueue({type: "type_text", text})` — use the api() helper
         - On 202 response: `textarea.value = ''`, reload history, show toast "sent"
         - On non-202: show toast with error message from response body ("paused", "queue full", "text too long")
       - "backspace" button (FE-06):
         - Call `enqueue({type: "backspace"})`
         - Show toast "backspace sent" on 202, error toast otherwise
       - "Clear text" button (FE-08):
         - `textarea.value = ''` — NO HTTP request
         - Focus the textarea
       - "Clear PC field" button (FE-09):
         - Call `enqueue({type: "clear_pc_field"})`
         - Show toast "clear sent" on 202, error toast otherwise
       - "enter" button (FE-07):
         - Call `enqueue({type: "enter"})`
         - Show toast "enter sent" on 202, error toast otherwise

    5. **Status polling** (FE-10):
       - `function updateStatus()`:
         - fetch GET /api/status via api() helper
         - Parse JSON response
         - If `enabled === true`: add `ok` class to `#pill`, set `#pill-text` to "enabled"
         - If `enabled === false`: remove `ok` class from `#pill`, set `#pill-text` to "paused"
         - On fetch error: set `#pill-text` to "offline", remove `ok` class
       - `setInterval(updateStatus, 5000)` and call immediately on page load

    6. **History** (FE-11):
       - `function loadHistory()`:
         - fetch GET /api/history via api() helper
         - Parse JSON array of strings
         - Get `#history-box` and `#history-list` elements
         - If empty: add `.hidden` class to history-box, clear list
         - If entries exist: remove `.hidden` from history-box, render each entry as a `.history-item` div
         - Each history item: click handler copies the text to textarea (latest entry goes first — the server returns newest-first)
       - Call `loadHistory()` on page load
       - Call `loadHistory()` after each successful (202) send

    7. **Toast**:
       - `function showToast(msg, isError)`:
         - Get `#toast` element
         - Set `textContent` to msg
         - Add `show` class
         - On error: optionally tint red (but keep simple, existing CSS is fine)
         - `setTimeout(() => toast.classList.remove('show'), 2000)` — clear after 2s
       - Call `showToast()` for successful actions ("sent", "backspace sent", etc.) and errors ("queue full", "paused", etc.)

    8. **Guard**: Wrap all DOM access in `DOMContentLoaded` listener to ensure elements exist before binding handlers.

    IMPORTANT implementation rules:
    - All DOM access happens inside `DOMContentLoaded` to avoid NPEs
    - The Promise queue must actually serialize: each `enqueue` returns `queue = queue.then(() => fetch(...)).then(...)` — the caller must NOT await/use the returned promise for side effects that happen out of order
    - History box hidden class toggling must handle the empty/loading states correctly
    - No external script references, no CDN, no inline event handlers (`onclick` attributes) — all via `addEventListener`
    - Keep the code readable but minimal — ~150-200 lines of JS is the target

## STRIDE Threat Register

|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Information Disclosure | Token in URL | mitigate | AUTH-04: `history.replaceState()` removes token from address bar immediately after extraction |
| T-02-05 | Information Disclosure | Token in sessionStorage | accept | sessionStorage is scoped to the current tab and cleared when the tab closes. No other tabs/Windows can read it. This is a LAN-local tool with physical access required. |
| T-02-06 | Tampering | XSS via input paste | mitigate | The textarea input is sent as a fetch body to the server; no DOM injection occurs on the phone page. The server receives JSON and processes it as KeyCommands via clipboard/paste — not evaluated as code. |
| T-02-07 | Repudiation | Concurrent fetch races | mitigate | FE-04: Promise chain queue serializes all commands — the next fetch only fires after the previous completes |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new dependencies in this plan |
